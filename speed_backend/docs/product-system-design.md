# 订阅商品系统

本次已实现后台套餐配置、客户前台购买与订单、支付核验和订阅权益处理。参考本地 V2Board 的套餐与订单逻辑，复用现有支付中心、订阅流量统计和节点同步能力。

## 已实现规则

- 每个租户、会员只有一个当前订阅账户，数据库唯一约束为 `(tenant_id,user_id)`；新购、续订、升级、流量加购和后台权益操作通过账户行锁串行处理。暂停、耗尽和未开始但未到期的订阅仍占用有效订阅名额；过期或已结束订阅不占用。
- 新购创建订阅；续订、升级、加购修改当前订阅，保留订阅编号和链接。过期或已结束后可直接购买新订阅，保留旧订阅和订单历史；旧节点撤销由同步任务继续处理。
- 周期价格按自然月配置，支持 1–36 个月、多档价格。人民币金额保存为分，流量保存为字节，界面使用 GiB。
- 续订从 `max(当前时间,原到期时间)` 延长。未过期续订保留本周期已用量和剩余补充流量；实际过期后续订不会恢复已失效补充流量。
- 补充流量只能加到未过期的当前有限流量套餐，不延长有效期。先消费套餐周期额度，再依次消费补充流量；每月/间隔重置保留剩余补充余额。
- 升级只允许更高的套餐等级。按旧已完成周期订单的原价快照 × 剩余秒数 / 该段总秒数折抵，包含提前续订的未来周期；原折抵权益仅核销一次。折抵最高为新订单价格，超过部分目前不退款、不存入余额。目标套餐从履约时开始新的购买周期，重置周期使用量，历史累计使用量保留；未过期补充余额转入当前订阅。
- 展示、新购、续订分别控制。隐藏当前套餐仍可被拥有者查询，停止新购仍可续订（需续订开关开启）。发布后的修改不自动修改存量权益；购买时固定价格、规则和节点快照。
- 套餐容量计入未过期当前订阅与待支付/已付款异常订单占用。节点实际可用性由现有节点分配链路验证，资源不足保持权益异常状态。

升级起点、抵扣上限及跨周期补充余额保留，是这版采用的明确规则，并在客户结算页说明；后续可按运营需求调整。

## 表与状态

| 表 | 职责 |
| --- | --- |
| `subscription_plan` | 名称、介绍、等级、展示/新购/续订开关、周期流量、重置方式、节点上限、销售容量 |
| `subscription_plan_price` | 周期售价或补充流量售价 |
| `subscription_plan_node` | 已上架出口节点、服务器入站、用户连接地址 |
| `subscription_account` | 当前订阅指针、业务版本、有效订阅冲突标记 |
| `subscription_purchase` | 购买快照、原价/抵扣/应付、支付单、有效期、权益处理结果 |
| `subscription_traffic_pack` | 补充流量来源和剩余余额，来源订单唯一 |

现有 `subscription` 增加套餐来源、基础流量与补充流量周期消耗字段。

订单状态：`pending` 待支付，`paid` 待权益处理，`completed` 权益已发放，`failed` 已付款权益异常，`cancelled` 未付款取消/过期。节点配置继续独立使用订阅的同步状态；权益已发放不表示远端节点已配置完成。

下单幂等键和账户锁防止重复下单/重复履约。同一会员一次只允许一笔未结束订单。核验服务端支付单状态、金额和商户订单号，不接受客户端声称付款成功。后台修改权益后，旧订单版本不匹配会进入异常处理。订单取消后迟到付款也保留为异常，不静默发放。每 15 秒轮换核验待处理订单，后台订单页可重试。

## 前后台

后台新增「订阅管理 → 套餐商品 / 套餐订单」，权限分别为 `subscription:plan:manage` 与 `subscription:order:manage`。套餐节点配置复用原订阅入站选择器。

客户前台的首页、套餐、订单、流量、节点与订阅入口使用真实数据，可新购、续订、升级、加购、取消未付订单、继续支付、刷新履约状态和复制已核对订阅链接。

支付入口展示已配置的支付宝网页/扫码、微信扫码/H5及测试渠道，支持 URL 跳转和二维码；不展示需要额外用户身份或原生客户端的渠道。测试支付只用于开发，生产环境应禁用。

客户后台 `/custom-api/packages/*` 固定代理主后台 `/app-api/subscription-products/*`，使用现有会员会话验证和服务端租户配置。主后台再次验证会话，不使用客户端提供的会员、租户或价格。

## 启用步骤

1. 启动主后台运行 Flyway V9：隐藏 AI/IoT/IM/MP 菜单；补齐商城/支付结构；建立订阅商品表；修正支付可选字段和后台任务审计字段；增加订单轮换核验字段、节点权限组并放宽商品可选字段。保留原数据，不能跳过迁移。
2. 客户后台与主后台连接同一个数据库，客户后台先运行自己的认证表迁移。设置 `CUSTOM_BACKEND_URL` 为主后台内部地址、`CUSTOM_TENANT_ID` 为对应租户。
3. 在支付管理中配置迁移建立的 `subscription` 应用及真实渠道凭据，核对业务通知地址 `/app-api/subscription-products/notify`。迁移中的本机默认地址需按部署拓扑配置；新建租户须自行建立该支付应用。
4. 在套餐商品中配置售价和真实可用节点/入站，开启展示和新购。普通角色需要分配新增菜单权限。
5. 重新构建并部署主后台、客户后台、管理前台和客户前台。客户网站将 `/custom-api` 代理到客户后台，将 `/app-api/subscription/feed` 代理到主后台，避免复制出的订阅链接指向客户站的静态页面。生产跨域时配置 `CUSTOM_CORS_ORIGIN`。

开发前台可用 `CUSTOM_API_PROXY`、`SUBSCRIPTION_API_PROXY` 指定测试后台地址；默认仍为 48081 和 48080。

## 历史数据与范围

账户锁定时只检查未结束且未到期的订阅，存在多份有效订阅时阻止购买；过期历史不构成冲突，不自动删除历史。人工创建的有效订阅不强行关联套餐，其商业升级需人工处理。过期后购买同套餐或其他在售套餐均按新购处理，不受旧套餐等级或续订开关限制；已过期或结束的订阅不能续费或后台延长，只能购买新订阅；未过期订阅延长时也检查有效订阅冲突。

第一版未实现自动退款、抵扣余额账户、降级、无固定期限套餐、V2Board 历史数据导入、限速、在线设备数限制及完整独立节点列表。现有节点数量上限不等于在线设备限制。前台工单等其他原有占位功能不在本次商品改造范围内。

验证使用独立临时 MariaDB、Redis 和测试账号，不写入生产业务库。单元测试验证订阅唯一性、抵扣、重复履约、租户/用户隔离、容量、过期加购、续订保留余额和重置规则；真实接口验证迁移、套餐查询、创建支付单、幂等和取消订单，以及模拟付款后的续订、补充流量、重复回调、周期重置保留余额及过期后续订不恢复余额（使用无远端客户端的测试订阅）。真实支付渠道及远端节点连通性仍需部署环境验收。

## 商品字段必填调整（V9，原 V15）

套餐保存只要求名称和流量额度（支持 0 和小数 GiB）。介绍、等级/排序、容量、价格名称、各周期售价和节点配置均可留空；缺省等级/节点上限为 1，容量/排序为 0，介绍为空，默认允许续订。空售价不创建报价，0 元是免费报价，不能混淆。已有报价可以单独停用。实际购买前仍校验报价、对应套餐和可用节点配置。

节点权限组可复用出口节点/服务器/入站组合，套餐可选一个组；专用节点配置优先，组内按节点上限分配。组内修改只影响下一笔订单的节点快照。组可以先建立为空，再完善节点配置。

接口支持 V2Board 核心字段名 `content`、`transfer_enable`（GiB）、`group_id`、`show`、`renew`、`capacity_limit`、六档周期价格和 `reset_price`。`reset_traffic_method` 0–4 分别映射月首、月到期日、不重置、年首、年到期日，空值使用本系统默认重置规则。流量重置售价只重置当前套餐周期用量，保留补充余额，不延长订阅；其付款不会计入时间权益折抵。

一次性无固定期限套餐和套餐限速仍未开放，对非空一次性价格、非零限速会明确拒绝保存，避免字段看似保存却不生效；留空不会阻止保存。这是当前执行链路的能力范围，不把这些字段标为必填。

原商城 SPU 的分类、品牌、关键词、简介、详情、封面/轮播、市场价/成本价、配送和营销设置同步改为选填，并调整新增/更新校验、清空字段及数据库约束。原商城保留商品名称、SKU 售价/库存这类真实交易必需项；选择快递时表单仍要求运费模板。订阅售卖继续使用套餐订单链路，不会因放宽普通商品字段而自动进入订阅履约。

## 后台订阅商品列表（V9，原 V16）

原商品列表入口改为订阅套餐管理，普通商品新增、编辑、详情链接返回订阅商品列表，避免将旧 SPU 编号当成套餐编号。列表展示可售订阅月数和价格、周期流量、重置规则、节点地区、权限组、节点上限、补充流量和重置服务、升级等级、展示与新购/续订规则。地区来自实际节点绑定，专用节点优先，否则使用权限组按节点上限选取的节点；未配置地区明确提示，不虚构覆盖范围。

V9 隐藏商品分类、品牌、属性、评论菜单并将商品列表更名为订阅商品，保留原商城数据。管理账号需要 `subscription:plan:manage` 权限；该权限可以读取配置节点选项和入站。部署后重新登录以刷新缓存菜单。

## 旧商城菜单清理（V9，原 V19）

订阅商品和套餐订单统一从「订阅管理 → 套餐商品 / 套餐订单」进入。V9 隐藏整个 MALL 菜单树，包括重复的订阅商品入口、旧实物订单和售后、配送、自提、分销、营销、内容装修、客服及商品/交易统计；会员统计迁移到「会员中心 → 会员统计」。保留旧页面路由、权限、后台模块和全部历史业务数据，隐藏菜单不等于停用 API。旧商品列表及新增/编辑/详情链接跳转到 `/subscription/plans`。

部署时启动主后台执行 V9，再部署管理前台并重新登录刷新菜单缓存。支付中心、会员中心和订阅履约链路保留。
