# SOCKS5 节点管理（第一版）

管理后台入口：Xray 管理 → 节点管理，路由 `/xray/node`。

## 启用

后端使用项目要求的 JDK 25。启动更新后的管理后端时，Flyway 执行
`V8__xray_and_subscription_management.sql`（包含原 V8～V16），创建节点、服务器关联、检测日志、操作任务和预留领用表，并添加菜单权限。
已有角色需要分配节点菜单及操作权限；重新登录以刷新菜单。
无需手动执行迁移 SQL，否则可能导致 Flyway 重复建表。

## 已实现

- 手工新增和修改：IPv4、IPv6、域名、无认证或用户名密码认证。
- 文本批量导入：每行一条，支持 `地址:端口:账号:密码`、`socks5://` 和 `socks://`，最多 500 行、200000 字符。
- 导入前逐行预览有效、重复、错误项；只导入有效项；不静默覆盖密码。
- 地址转小写、去末尾点和 IPv6 外层方括号；按租户内地址、端口和认证账号去重。
- 新节点默认下架；编辑时密码留空保留原密码；改动连接信息将自动下架，确认后可重新上架；已有服务器配置标记待同步。
- 单个和批量上下架：上架仅修改允许订阅领用的状态，不要求检测成功或已有服务器部署，不进行远端操作。
- 普通下架禁止新领用，保留原有授权。上下架不会删除服务器出站。
- 后台批量检测任务、逐项结果、重试失败项、最近 50 次日志。
- 保留 SOCKS5 出站部署底层接口供后续订阅模块复用；节点页面不再提供提前部署入口，仍可查看已部署记录、核对和移除出站。
- 节点统计、名称/地址/标签、地区、上下架和检测状态筛选。
- 数据租户隔离、操作权限、密码加密；列表和详情不返回节点密码，导入文本不写 API 请求日志。

连接格式示例（简写格式的账号和密码按原文处理，密码可包含冒号；URI 格式的特殊字符可用 URL 编码。IPv6 简写地址需要方括号）：

```text
1.2.3.4:1080:username:password
socks5://1.2.3.4:1080#无认证节点
socks5://username:password@1.2.3.4:1080#香港节点
socks5://username:password@[2001:db8::1]:1080#IPv6节点
```

## 检测含义

管理后端依次完成：公网地址解析、TCP 连接、SOCKS5 方法协商、认证、CONNECT、HTTPS 请求。
固定检测目标为 `https://www.gstatic.com/generate_204`，期望 HTTP 204；TLS 校验证书与主机名。
禁止检测回环、私网、链路本地、共享地址等非公网节点。
耗时是整个代理请求耗时，不是 ICMP 延迟。结果仅代表管理后端的 TCP 出口，不代表 UDP 或每台服务器的网络。
检测异常标记状态，不自动下架。

## 按订阅领用部署

业务顺序为：新增/导入 → 上架 → 用户订阅领用 → 检测节点、分配服务器 → 部署与回读核对 → 开通授权和生成订阅。
上架是纯本地业务状态，不自动检测、不上传、不建立用户授权；检测结果只作参考，检测异常和过期不阻止上架。
实际领用应检查节点仍已上架、检测可用，并在服务器配置及用户路由成功后才将授权标记生效。
同一节点与服务器的当前版本配置可复用，避免每个用户重复上传；部署失败不可返回可用订阅，应保持待开通/失败并支持重试。
订阅模块目前尚未实现，因此上述按领用部署流程是后续接入约定，本版没有虚构订阅事件。

## 服务器部署含义与限制

使用官方 3x-ui Xray 配置 API：`POST /panel/api/xray/` 和 `POST /panel/api/xray/update`，
读取 `xraySetting`，使用表单提交，保留 `outboundTestUrl`。
来源：https://github.com/MHSanaei/3x-ui/blob/main/internal/web/controller/xray_setting.go

每个节点在远端生成 `speednet-node-{tenantId}-{nodeId}` 的专属出站，保留其他出站、路由、DNS及额外配置。
已有专属出站原位置和附加字段保持；新出站追加，避免改变默认出口。
远端没有默认出站或存在重复/冲突标识时拒绝修改。
写入成功后再次读取核对，才能标记“配置已核对”。它不代表实时运行验证或用户路由已开通。
面板写配置可能重启 Xray；不支持该 API 的旧面板返回明确失败，不回退到直接覆盖服务器文件。
移除前要求节点已下架、没有有效领用，并拒绝移除仍被路由、负载均衡或默认出口引用的出站。
核对支持已记录服务器关联；不扫描或认领远端手工添加的未知出站。

任务持久化到数据库，但执行器和配置锁当前按单个管理后端实例工作。
服务重启将未完成任务标记失败，需核对远端后重试，避免自动重放不确定的写入。
当前不支持多实例同时修改同一服务器；远端面板人工编辑也应避开部署任务。
尚未在真实 3x-ui 服务器上完成联调。

## 订阅接入边界

项目当前没有套餐和订阅生命周期，因此本版预留 `xray_node_assignment`，提供领用明细和去重人数查询，
但不创建虚构订阅或开放手工写入领用接口。页面明确提示订阅尚未接入。

后续订阅模块需统一维护订阅状态、到期时间、用户入站凭据及用户到出站的路由，
生成服务器连接供客户端订阅，外部 SOCKS5 密码留在服务端。
有效领用人数按有效期内且授权已生效的用户去重；不是实时在线人数。
到期撤销、立即停用已有用户、服务器侧检测、流量/活跃数据和自动故障迁移尚未实现。
领用表到期时间是未来集成的投影字段，接入正式订阅表后应以订阅数据为唯一来源。

节点、地区及城市共 36 项测试覆盖连接解析、凭据脱敏、批量导入、上下架约束、密码保留、真实回环 SOCKS5 握手、配置保护和部署回读。

## 地区与城市管理

入口：Xray 管理 → 地区与城市管理（`/xray/region`）。采用“地区 → 城市”两级结构，例如美国 → 纽约、日本 → 东京。
地区和城市分别支持新增、改名、排序、启用和停用。城市归属于一个地区，在该地区内名称唯一；地区名称在租户内唯一。
展开地区即可维护其城市。城市所属地区建立后不允许直接修改，避免使已有节点关联不一致。

节点创建、编辑、列表筛选均采用两级下拉；切换地区自动清空城市，只列出该地区的城市。
批量导入为本批节点选择地区与城市；节点列表展示“美国-纽约”，详情分别展示地区和城市。
后端接收 `regionId` 与 `cityId`，校验当前租户中的地区和城市存在、归属关系匹配，不能提交任意名称或跨地区组合。
新节点只能选择启用的地区及城市；停用任一层后保留原有节点关联，编辑原有节点可以保留该组合。
改名后节点展示同步更新，地理信息变化不会触发连接配置版本更新。

V12 将原有非空手填地区按租户迁移为管理项并建立关联。V13 保留已有地区，新增城市层级；不推断已有节点的城市。
原来没有城市的节点显示未分配，编辑保存时必须选择城市。旧 `region` 列仅为迁移兼容保留，应用不再写入该列。
城市操作沿用地区管理权限，菜单名称随 V13 更新为“地区与城市管理”。
